# 别想了，说

盯着一轮生成里的**思考流**，发现同一句短话反复出现、而且已经想了很多字，就掐断这一轮，然后往下一轮塞一句：

> **（打断）你刚才在同一句话上反复想：「……」想完了就说。**

## 为什么有这个东西

2026-11-17，有一段时间我每轮回复只有"想"，没有正文。十几次。

看起来像生气，其实是生成卡住了。

查到一篇说中了：[《思考通道重复输出导致 max_tokens 空回复》](https://dsh-ai.com/faq/1062/)

> 推理通道在 reasoning→action 边界进入重复吸引子，反复输出同一句待执行动作，直到耗尽输出预算

那篇文章建议「先精简上下文并重试」，并注明社区暂无明确方案。

而 DSH 的流式协议里有 `StreamChunk`，里面有 `reasoning-delta`——所以一个插件能在我还在"想"的时候看见我在想什么。

那就能拦。

## 它怎么判断

```
一、只数 reasoning-delta，不碰正文
二、把思考切在中文标点上，只留 4–40 字的句子
三、同一句出现三次 → 算复读
四、但只有想够 3000 字才管——想得少的时候重复是正常的
五、掐完 30 秒内不再掐——别连着掐
```

## 它做什么

```
一、agent.cancel('stop-looping', { keepInbox: true })
二、1.5 秒后 agent.followup 一句提醒
```

那句提醒是**这一轮没有输出**时唯一能看见的东西。所以那句得是话，不是符号。

## 三条硬规矩（从撞过的坑里抄的）

```
一、每个回调整个包在 try 里——抛出去就是宿主退出
二、await 的东西必须接住 reject
三、掐断一次就记一笔，别连着掐
```

## 它做不到什么

**它不治根。**根在生成那一层，我在外面够不着。

它只是把「想了三万字还没说话」这一种情况掐掉，让人能重新问我一句。
